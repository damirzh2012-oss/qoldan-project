# QOLDAN v0.3 — инструкция Дамиру (прочитай сначала)

## Что исправлено
- Сайт и логотип теперь расположены **в корне репозитория**, поэтому загрузка файлов через GitHub проще.
- `netlify.toml` создаёт папку `dist` при сборке. Netlify публикует именно `dist`, не `site`.
- Функция OpenRouter находится в `netlify/functions/ai.mjs`, API-ключ не включён в файлы.
- Автозапуск сборки **не требует npm** или установки фреймворков.

## ВАЖНО: две независимые ошибки Netlify
**1) `Deploy directory 'site' does not exist`.** Исправляется новой структурой файлов + `netlify.toml`, как в ZIP.
**2) `Unrecognized Git contributor` на PRIVATE GitHub repo.** Не исправляется ZIP-файлом; ограничение Netlify Free для приватных репозиториев с несколькими авторами. Бесплатные варианты: (а) сделать репозиторий **публичным** и работать через GitHub (в репозитории не должно быть секретов!), (б) использовать только привязанный Git-аккаунт владельца Netlify для коммитов или попросить владельца самостоятельно публиковать изменения, (в) владелец Netlify делает ручной deploy через Netlify CLI. Не покупайте Pro лишь ради этой проблемы, если вас устраивает публичный исходный код.

## Самый простой рекомендуемый путь: GitHub → Netlify
1. Сначала у владельца OpenRouter **отозвать API-ключ, отправленный в чат**, и создать новый. **Никому не пересылать его в Telegram/GitHub/ChatGPT.**
2. Владелец репозитория решает, делать ли его Public (GitHub → Settings → General → Danger Zone → Change repository visibility); публичный исходный код подходит, если в нём нет секретов. Если repo остаётся Private — коммиты для автосборки должны поступать от разрешённого contributor в Netlify.
3. **Распаковать этот ZIP**. В GitHub загрузить его содержимое в КОРЕНЬ репозитория, не папку `qoldan_damir_ready`: `index.html`, `app.js`, `styles.css`, `qoldan-logo.webp`, `favicon.svg`, `netlify.toml`, папку `netlify/functions/ai.mjs`. Старый `site/` можно удалить ПОСЛЕ успешной проверки нового деплоя, чтобы не путаться.
   - GitHub Desktop удобнее для папки `netlify/functions`: локально клонировать репозиторий, скопировать содержимое ZIP в корень, Commit → Push.
   - Если только веб-интерфейс GitHub: корневые файлы загрузить через Add file → Upload files, а функцию создать через Add file → Create new file с именем `netlify/functions/ai.mjs` и вставить текст из ZIP.
4. Netlify → проект `qoldan2026` → Project configuration / Build & deploy: проверьте, что Base directory пустая (корень репозитория), Build command не конфликтует с `netlify.toml`, Publish directory = `dist` (если UI не переопределяет файл). Site не должен ожидать `site`.
5. Запустится deploy после Commit/Push. Если заблокирован `Unrecognized contributor`, исправить п. 2. Если сборка не стартует, смотрите Deploy logs / Trigger deploy после изменения настроек.
6. ПРОВЕРКА САЙТА: открыть адрес Netlify в инкогнито. Должен появиться новый дизайн, логотип, Explorer и Researcher.
7. ПРОВЕРКА ФУНКЦИИ: открыть `https://ВАШ_ДОМЕН.netlify.app/.netlify/functions/ai` в браузере. Ожидается JSON с `Method not allowed` (405). Если 404 — функция не развернулась.
8. AI: владелец Netlify → Environment variables → Add a variable: имя `OPENROUTER_API_KEY`, значение **новый ключ**, scope Functions/All. После сохранения новый deploy. Для текста scientific background нажмите Check reasoning. Важно: free-модель `openrouter/free` может быть недоступна по квоте и это не ошибка сборки.

## Проверка учебной механики
- Explorer → сначала карточки/подсказки, затем 3 Ω (перегрузка), 4 Ω (батарея кончится рано), 8 Ω (мало мощности), 6 Ω (верно).
- Researcher → Scientific Background → Plan → расчёты (6 Ω: 2 A, 24 W, 2 h) → Justification → Transfer (8 Ω: 3 A, 72 W, 2 h) → Report.
- Ответы хранятся в браузере пользователя, **не в общей базе**. Участник вручную выгружает JSON.

## Если публичный репозиторий не подходит
Используйте пакет `QOLDAN_DAMIR_STATIC_ONLY.zip` и ручную загрузку в Netlify в том же проекте. Это публикует интерфейс, но **не подключает серверную функцию ИИ**. Для ИИ потребуется Git-деплой или Netlify CLI с авторизованным владельцем.

## Безопасность и ограничения
- **Не включайте ключ в GitHub, HTML, JavaScript или ZIP**.
- Не публикуйте персональные данные детей, ограничьте объём текста и не используйте AI-ответы как официальные оценки.
- Встроенное ограничение запросов не является сильной защитой для большого публичного трафика: для широкого запуска нужен общий серверный лимитер, мониторинг и защитные меры.
- Загрузка ZIP сама по себе не решает ошибку `Unrecognized contributor`.
